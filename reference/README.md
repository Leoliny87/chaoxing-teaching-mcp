# 未部署参考：作业契约与等待方法

这些文件来自项目自身的未部署研究，不包含厂商扩展、私有宿主实现、认证或现场对象。它们不在 `server/` 包中，不被 `scripts/launch_stdio.py` 或工具注册表导入，也不包含 MCP 启动入口。隔离依据是明确的导入边界和功能裁剪，不是文件后缀。

- `assignment_contracts.py`：仅保留请求摘要、空白编辑器验证、原始文本期望三个纯函数；原项目异常类型改为 `ValueError`。没有保存、发布、删除、文件日志或浏览器操作代码。
- `passive_wait.py`：依赖 `self.here`、时钟和休眠的方法适配，不是纯函数。只允许成功但为假的观察结果继续等待，任何异常向上传播。它没有自动恢复或重试被拒操作。

`scripts/run_offline_tests.py --reference` 显式在单独测试进程中通过 `XxtBase.wait_for = prototype.wait_for` monkeypatch 替换等待方法，运行原 111 项和 5 项作业契约测试，共 116 项通过。默认启动和默认测试不加载这些参考；磁盘上的运行源码保持原样。默认完整集合仍有 3 个失败子测试，合成日志审计仍有 3 类输出风险；参考模式通过不代表默认核心已修复，也不能代替作业保存、删除、讨论或真实控件验收。测试运行器提供防误调用的进程内保护，不是恶意代码沙箱。

## 讨论入口的交接设计

未部署讨论候选尝试先确认当前课程、唯一可见的讨论入口及其原始文本，再检查 iframe 内外的命中点是否确属目标。存在加载遮罩、重复入口、观察不完整或权限拒绝时停止，不移除遮罩，不直接执行 DOM 点击。成功导航后还要验证讨论 iframe 的 HTTPS 域名、路径和课程绑定。

本批仅交接这一设计说明，没有把包含真实导航和点击的候选整体复制进来。后续实现需要重新取得正常页面观察和明确受控的验收条件，不得把这份说明当作对拒绝操作的重试许可。

## 历史通知门控的可复用思路

旧通知原型强调完整分页快照、精确对象身份、参数摘要、过期检查、单次执行，以及结果未知时先核查而不再次提交。人工批准应由宿主可信来源绑定到本次具体操作；计划编号本身不是批准。

旧原型的完整代码和驱动未纳入本批：它使用另一套适配接口，尚未按本批运行器重新验证，不能作为当前 MCP 的直接替换。当前通知回归测试已覆盖发布记录与关联活动的精确绑定、受众变化及重复提交保护的部分边界。

项目仍未选定统一开源许可证，本批未新增许可证或重许可。
