## 执行方式

在项目的独立 Python 环境中运行。需要已安装的 Node.js 来执行一组完全合成的 JavaScript 解析夹具；缺少 Node 时立即报错，不跳过测试。

```sh
.venv/bin/python -I scripts/run_offline_tests.py --guard-selftest
.venv/bin/python -I scripts/run_offline_tests.py --suite compatibility
.venv/bin/python -I scripts/run_offline_tests.py
.venv/bin/python -I scripts/run_offline_tests.py --audit-logs
.venv/bin/python -I scripts/run_offline_tests.py --reference
```

revision2 的实际复测环境为 CPython 3.14.4。两个参考模块均可导入，类型注解可解析；等待方法已补上 `typing.Any` 导入。PATH 及常见可执行目录中没有可用的 Python 3.10–3.13，未安装其他解释器。另用 `ast.parse(feature_version=(3, 10))` 检查了参考模块语法；这不是低版本运行验证，不能宣称已通过 Python 3.10–3.13。

默认核心的三个失败分别是等待逻辑吞掉 `timeout`、`control_not_ready` 和页面脚本错误后继续轮询。参考等待逻辑只把成功返回的假值作为继续等待的条件；异常原样向上传播。日志的三个风险没有被参考等待逻辑修复。

## 隔离范围与实际限制

运行器在导入项目之前清除本测试进程继承的环境，设置合成实例名，并把配置、状态、临时文件和 Python 主目录解析放入一次性临时目录。没有重设系统或用户的 `HOME`。全局 Chrome 策略路径在测试中替换为不存在的合成文件。

Python 审计钩子拒绝网络访问、非允许子进程及许可目录外的文件读写。只允许指定 Node 二进制运行内存中的 `-e` 夹具，并预加载限制网络、文件访问和子进程的守卫。运行器只允许读取本项目、临时目录和当前解释器依赖目录；写入限于临时目录。

当前 MCP SDK 导入期间有 2 次目录探测和 2 次文件探测被守卫阻断，测试仍继续运行；报告保留类别和源码调用位置，不记录被访问路径或内容。没有读取这些被阻断的资源。此守卫用于防止已审查测试的意外访问，并非针对恶意 Python/native 代码的操作系统沙箱。运行不可信新测试时应另用一次性隔离环境。

不要绕过本运行器直接执行测试模块或日志审计脚本，否则临时状态及 I/O 隔离不生效。

## 夹具来源

`tests/fixtures/synthetic_data.py` 在本地用常量表达式生成 6 个十进制标识和 20 个显式合成控制标记，不读取账户、页面、配置或外部文件。测试通过这些常量构造 mock 返回值及期望值。短数字状态码、序号、命令参数和不匹配样例仍是测试就地定义的协议输入。

日志回归中的假秘密、错误文本、网址和人名标记均由测试代码直接构造；例如合成标记使用 `SYNTHETIC_` 前缀，网址使用保留的示例域名。扫描和测试没有读取真实密钥作为样本。
